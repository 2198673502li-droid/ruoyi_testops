# 面试问答（12 题）

> 用法：每条先自己答一遍（对着摄像头），再回来补要点。目标：连续讲 5 分钟不卡。

## 1. 你这套和"用 Postman 点两下"的本质区别是什么？
答（⏳）：
提示：可回归、可断言到库、可进 CI、失败有现场、分层可维护；Postman 是手工探索，不能防回归。

## 2. 用例怎么保证覆盖？为什么是 110 条而不是 500 条？
答（⏳）：
提示：四板斧 × 模块矩阵推导出来的，不是凑数；按 P0/P1/P2 分级，风险优先。

## 3. token 怎么管理？会话级 fixture 有什么坑？
答：session 级 `admin_token` 只登录一次；但 `/logout` 会让该 token 失效，所以登出/改密类用例用独立 `fresh_token`，否则"一条用例污染整轮"。

## 4. 用例之间有依赖怎么办？数据怎么清理？
答（⏳）：
提示：`data_factory` 造唯一后缀数据（`autotest_<ts>`），teardown 兜底删；用例之间不共享业务数据。

## 5. 怎么能保证测试环境一致？
答（⏳）：
提示：镜像锁版本（不用 latest）+ 初始化 SQL 进镜像 + `down -v` 可重建 + 一份 `.env.example`。

## 6. Docker 网络你怎么规划的？为什么 Jenkins 要接 external 网络？
答（⏳）：
提示：`ruoyi-net` 由脚本创建为 external，应用栈和 Jenkins 各自一个 compose 项目接入同一张网，才能用服务名互访（`backend:8080`），并且 `down -v` 不会误杀 Jenkins。

## 7. 为什么 Jenkins 要挂 docker.sock？有什么风险？生产怎么改？
答（⏳）：
提示：容器里没有 daemon，挂 socket 才能调宿主 docker；风险=容器内进程等于宿主 root；生产换 rootless docker / DinD / 独立 agent。

## 8. 为什么 bind mount 在你的方案里不能用？
答：Jenkins 在容器里、通过 `docker.sock` 调**宿主** Docker，compose 里的 bind mount 路径由宿主解析；容器内的 `/workspace/init` 在宿主上不存在，Docker 会静默建个空目录 → 容器起来了但库里没表、nginx 403。改用 `COPY` 进镜像即可。

## 9. 若依的权限模型你怎么测的？`@PreAuthorize` 和数据权限有什么区别？
答（⏳）：
提示：前者是"能不能调这个接口"（功能权限，`@ss.hasPermi`），后者是"能看到哪些行"（数据范围，`@DataScope` 拼 SQL）；越权用例要两条都覆盖。

## 10. 你发现了什么 bug？
答（⏳）：见 `docs/缺陷记录.md` 三条，按「现象 / 复现 / 影响面 / 建议」讲。

## 11. 失败率怎么治理？flaky 怎么定位？
答（⏳）：
提示：不用 sleep 用轮询、数据隔离（唯一后缀）、失败附请求+响应+耗时、连跑 3 次仍失败才判定真 bug。

## 12. 如果接口有 1000 个，你怎么扩展？
答（⏳）：
提示：OpenAPI 契约驱动生成骨架 + 风险分级只深测核心链路 + 数据驱动 + 并行（xdist）+ 分层复用。
